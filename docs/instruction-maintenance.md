# 指令与可选 Skills 的维护

仅在修改项目指令、评估第三方 Skill 或排查 Agent 工作流问题时阅读本页。当前模板没有正式 SKILL.md，也不自动安装 Skills 或绑定模型。

## 内容归属

AGENTS.md 保留项目事实、命令、授权边界、资料路由和完成条件。docs/ 维护业务与工程规则的唯一来源；prompts/ 只提供任务输入和特定交付边界。删除重复规则时保留权威来源，避免把业务约束一起删除。
第一性原理与对抗性审查继续按风险使用，方法见 principles.md 与 review.md；不为小修改强制生成推导或审查报告。

## 何时增加 Skill

有反复发生的实际任务，且 Skill 能提供项目专有知识、可执行工具、特殊环境操作，或经过对照验证有效的流程时再添加。例如项目专用故障回放、数据迁移或小程序设备验收。
通用 TDD、调试、代码审查先复用现有文档，不仅因方法名称新增一层指令。业务术语与不变量可以直接维护在文档中。
第三方 Skill 逐个审阅其触发描述、工具/脚本、权限、依赖和与项目规则的冲突；引用或改编时保留必要来源与许可。不要整包默认加载。
描述简短且明确触发任务，详细流程和资源按需展开。入口不复制整套流程；不要写“涉及任何数据库活动都使用”这类宽泛触发。

## 调整后的评估

对同一模型、工具与代码起点，使用独立工作区对比修改前后指令：简单文案修改、业务规则功能、缺陷修复、高风险权限/迁移任务。固定验收与必需检查，记录实际模型与指令版本。
观察正确性、遗漏、有效发现/误报、重复确认、无效测试、耗时与可获取用量；必要时重复代表性样本，避免把单次波动当收益。先静态去重，再根据实际失败案例增加指令或 Skill。
模板脚本检查和示例通过不证明模型效率提高。本版本未运行模型行为对照评估，也未验证第三方 Skills 的效果。

## 设计参考

- [OpenAI Model guidance](https://developers.openai.com/api/docs/guides/latest-model)：审查 AGENTS.md/Skills 中对授权、委派、测试与完成条件的指令。
- [Eric Provencher：Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)：收紧触发、按需展开资料、减少过时的通用流程指导。

以上是设计参考；本模板保持模型中立，不将某一模型的建议强制应用于所有工具。需要时根据实际行为评估调整，不要求每次开发读取外部文章。
