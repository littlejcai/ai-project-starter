# 可选的子 Agent 协作

本页定义与具体工具无关的协作约定，不安装模型、不启动进程，也不提供自动调度器。使用者需要具备相应工具能力；按实际执行方式记录结果。
风险和审查标准沿用 [开发原则](principles.md) 与 [审查流程](review.md)，在现有任务中记录协作，不重复维护一套规则。

## 选择模式

存在范围清晰、可独立完成的子任务，且预期收益超过协调成本时，在工具与已有授权允许的情况下委派。没有适合拆分的任务则单 Agent 完成；不因任务被标为普通或高风险就机械增加角色。

| 模式 | 适用情况 | 执行方式 |
|---|---|---|
| 单 Agent | 文案、布局、边界明确的小修复 | 主 Agent 实现、验证和交付；低风险保持轻量 |
| 主 Agent + 审查子 Agent | 有明确独立审查价值、范围可限定的业务功能或重要修复 | 主 Agent 实现和自测，审查子 Agent 复查，主 Agent 处置并验证 |
| 主 Agent + 按需专项子 Agent | 高风险或复杂任务，且子任务可独立验收 | 方案/实现专项审查，或对职责独立的模块并行实施，主 Agent 统一集成 |

高风险任务仍需方案与实现阶段审查，但不因此强制固定数量的子 Agent。需求模糊、接口反复变更或多人争用同一文件时，先由主 Agent 澄清和收敛。
只委派有具体目标、输入与完成条件的任务；避免无收益地增加角色。低风险任务无需填写完整协作表。

## 职责与权限

主 Agent：维护目标、验收与任务状态，确定分工，保护用户已有变更，检查子 Agent 结果，处理冲突，运行最终集成验证并交付。
审查子 Agent：默认只读业务文件，依据需求、实际代码和测试找反例；可在隔离环境运行获授权的检查。结果返回主 Agent，由主 Agent 写入任务记录。
实现子 Agent：仅修改获分配范围，返回改动、测试与限制；越过文件边界、变更公共接口或调整业务规则前先协调。
子 Agent 不自行提交到默认分支、合并、部署或接受未解决风险，也不默认继续派生子 Agent；这些行动需要明确职责与已有授权支持。
所有委派遵守当前运行环境和用户授权；子 Agent 不能获得超过主任务允许范围的权限。不要以换角色或工具规避限制。

## 任务交接包

主 Agent 交付以下最小上下文，文件引用优先于复制长文：

1. 任务 ID、角色、目标、风险理由与完成条件。
2. 已确认需求/验收规则、接口约定、不变量的具体路径或摘录。
3. 审查或实现的基准提交、目标提交/工作区快照、相关差异。
4. 允许读取和修改的范围，共享文件/接口的协调责任。
5. 已有测试、运行命令、环境条件和证据位置；明确模拟与真实依赖边界。
6. 未知、限制、前置依赖和可接受的耗时/调用预算（按需）。

不能只传主 Agent 的完成总结。审查者先从需求和实际变更形成判断，再对照实现说明；可以看设计依据，不把开发者结论当作验收结论。
子 Agent 无法访问文件、运行环境或关键资料时，应报告缺失项，不根据摘要猜测代码。避免无关历史、密钥和生产数据进入交接。

## 审查协作循环

1. 主 Agent 固定待审查方案或实现版本；实现审查先完成相关自测，再使用 [子 Agent 审查提示](../prompts/subagent-review.md) 委派。
2. 子 Agent 返回审查范围、版本、发现及证据；缺陷/风险/建议和停止条件统一按 review.md。
3. 主 Agent 验证发现并记录采纳、驳回或待确认及依据；不因来自子 Agent 就自动接受结论，也不静默忽略阻塞项。
4. 修复后按影响范围复查。期间代码变化时标明原审查覆盖哪个版本，新变更不得直接沿用旧结论。
5. 主 Agent 在最终整合的版本执行相关检查，更新任务状态并交付；各子任务通过不等于整体通过。

重大歧义交给相应负责人；接受未解决风险仍需明确决定与授权。达到审查停止条件后结束，不固定凑问题数、不无限循环。

## 并行实现的前提

接口约定稳定、修改边界清晰、前置依赖就绪、结果可以独立验证，才考虑并行写代码。
每个实现任务使用独立分支/worktree 或工具等效隔离工作区，明确文件归属和公共接口负责人。不要在共享目录同时改同一文件。
框架不自动创建隔离环境；如果当前工具无法保证隔离，改为串行实现或只读专项审查。
主 Agent 统一合并、处理兼容与冲突、执行集成和必要界面测试；子 Agent 的局部测试不能替代这一步。

## 超时、不可用和降级

子任务失败、超时或预算耗尽时，返回已完成、失败/未执行项、证据和下一步；主 Agent 决定缩小范围、接手或更换方式，避免盲目重复调用。
没有子 Agent 能力时，使用独立会话或人工审查；仅能自审时明确写“自审”，不能冒充独立审查。
降级不能抹去必要验收：风险高且关键检查无法完成时，如实记录阻塞或待验证条件，按已有授权处理。
切换模型或会话可能增加视角，但并不保证独立性或正确性；最终判断以需求、代码、复现和测试证据为依据。

## 轻量记录与评估

采用委派时，在当前任务追加模式、分工、版本、读取/写入范围与工作区、结果和主 Agent 处置；必要时记录共享接口负责人、依赖与降级。最终整合版本和验证证据写入任务实际验证记录。不要默认保存所有子 Agent 原始对话。
先试跑 3–5 个合适功能，比较总耗时（包含协调、修复、复查）、有效缺陷、误报、返工和可获取的 AI 用量。再决定是否扩大并行开发。
