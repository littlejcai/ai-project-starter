# 按需使用子 Agent

有目标清晰、可独立完成且收益超过协调成本的子任务时，在工具与授权允许的情况下委派；其余由单 Agent 完成。风险分级决定审查深度，不固定角色数量。此模板不提供调度器或工作区隔离工具。

## 分工与权限

| 角色 | 职责与边界 |
|---|---|
| 主 Agent | 确定目标/验收、分工和文件归属，保护已有工作，处置发现、整合变更、最终验证并交付 |
| 审查子 Agent | 默认只读业务文件，可在指定隔离环境运行已授权检查；结果返回主 Agent，不改共享任务记录 |
| 实现子 Agent | 仅修改分配范围；变更公共接口、业务规则或超出文件边界前向主 Agent 协调 |

子 Agent 不默认继续派生，也不自行提交默认分支、合并、部署或接受未解决风险；此类行动须有明确职责及已有授权支持，权限不超过主任务。
并行写入要求接口稳定、依赖就绪、范围可独立验收，并使用独立分支/worktree 或等效隔离工作区。无法隔离或争用同一文件时串行处理，或只委派只读审查。

## 最小交接包

引用具体文件，避免复制无关历史或只发送完成摘要：

- 任务/角色、目标、风险理由与完成条件。
- 需求、验收、不变量、接口、代码与测试范围。
- 基准及目标提交/固定工作区快照、差异位置。
- 读取/写入边界、工作区及公共接口负责人。
- 命令、环境、已有证据及模拟/真实依赖边界。
- 依赖、未知、限制与预算（按需）。

方案或实现审查可使用 [委派提示](../prompts/subagent-review.md)，审查标准统一见 [review.md](review.md)。审查者先核对需求与实际变更，再对照开发者解释。

## 整合、记录与降级

主 Agent 固定待审版本；实现审查前完成相关自测。收到结果后验证发现，记录采纳、驳回或待确认及依据，在授权内修复并复查影响范围。
最终整合版本执行必要检查；新变更不能沿用失效的旧审查结论，各子任务通过不等于整体通过。停止与风险处置遵守审查标准。
在当前任务记录分工、范围/工作区、版本、证据、未执行项、主 Agent 处置及最终整合结果，不默认保存原始对话或敏感资料。
资料缺失、失败、超时或预算耗尽时，子 Agent 返回已完成、限制和下一步；主 Agent 接手、缩小范围或调整方式，不盲目重试。
工具不可用时可用独立会话或人工；只有自审就如实标注，不冒充独立审查。模型切换不保证正确性；关键验收缺失仍须记录阻塞。
评估是否扩大使用时，比较包含协调/修复的总耗时、有效发现、误报、返工及可获取用量，方法见 [指令维护](instruction-maintenance.md)。
