# 接口与数据约定

当前尚无真实业务接口，按项目选型建立以下约定。

根据选型选择一种主要约定格式，例如 HTTP API 的 OpenAPI、消息或输入的 JSON Schema，或技术栈支持的可生成运行时校验的 schema。
避免同时维护互不生成的多份字段定义；静态类型不能替代来自外部数据的运行时校验。

每条接口至少明确：

- 操作、调用方、请求与响应格式、必填/可空/默认值。
- 权限、资源归属、成功与失败状态码及错误码。
- 重复请求、幂等、超时、分页和时间语义（按需）。
- 关联业务规则 ID、兼容性与调用方影响。

数据库表结构不是公开接口。迁移脚本放入选定框架的迁移目录，位置在 architecture.md 中登记。
接口变化时同步约定、实现、调用方、测试；破坏性变化先处理兼容与数据迁移。
