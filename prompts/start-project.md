# 新项目启动任务

请先读取 AGENTS.md、docs/index.md、docs/status.md。
我的项目需求如下：【填入用户、场景、目标、平台及已有约束】。

请按此仓库流程推进：先总结产品范围、核心用户流程和验收例子，填写 docs/product.md；识别关键技术不确定性并先做必要的小验证；再形成最小技术方案和第一条完整业务任务。
能依据已知信息完成的部分直接完成；关键业务歧义集中提出，不自行发明产品规则。
选型后建立业务骨架、依赖安装与运行说明、真正的检查命令，接入 project.config.json。
不要一次写完整个项目的接口和自动测试；按功能小步推进。demo 通过不算业务完成。
结束时更新当前状态，列明实际验证、未执行项与下一步。

重要需求请按 docs/principles.md 的五问区分目标、事实/硬约束、假设、最小方案与关键实验，简短记录依据，不输出长篇推导。
确定任务风险并写理由，识别关键不变量。高风险在方案与实现阶段分别按 docs/review.md 审查；普通任务做一次实现审查，低风险保持轻量。
默认不强制多 Agent；接受未解决风险必须有相应负责人明确决定。
